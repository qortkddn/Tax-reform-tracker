# 프로젝트 일지

세법 개정을 AI로 추적·계산하는 트래커. 세법 지식 자체보다 **세법을 AI와 어떻게 엮어 일하는가**(역할 분담·검증·도구 연동)를 기록합니다.

## AI 활용 구조

| 단계 | AI가 한 일 | 내가 한 일 |
| --- | --- | --- |
| 조사 | 웹 검색으로 정부안·보도자료 수집, 출처 표시 | 의미 있는 항목 선별, 실질 영향 없는 항목 제외 기준 제시 |
| 설계 | 화면 구조와 계산 흐름 제안 | 핵심 가치 정의, 방향 수정(국회 심의 현황 → 본회의 통과·변경점) |
| 계산 | 세법 수식을 코드로 구현 | 세법 논리 오류 지적(누진세율, 등기/미등기, 재산 평가 기준) |
| 검증 | 헤드리스 브라우저 자동 테스트, 수계산 대조 | 세법적 타당성 검토, 출처 없는 부분 교재로 재검증 |
| 배포·기록 | GitHub 커밋, Pages 배포, 노션 일지 업데이트 | GitHub 앱·노션 연동 설정 |

## AI 활용 원칙

1. 숫자는 AI가 말로 추정하지 않고 코드로 계산한다
2. 미확정·미확인 정보는 화면에 '가정'으로 표시하고 출처를 붙인다
3. AI 결과는 반드시 실행해서 검증하고, 세법 지식으로 한 번 더 본다
4. AI가 출처 없이 쓴 내용은 스스로 밝히게 하고, 검증 책임은 내가 진다
5. AI에게 선별 기준을 준다 — 실질 영향이 있는 것만

## 2026.10.19 — 기획부터 배포까지 하루 만에

- **한 일**: 주제 선정 → 트래커 v1~v5 → GitHub Pages 배포 → Claude·GitHub·Notion 연동
- **AI 활용 방식**: 웹 검색으로 자료 수집 → 코드 구현 → 브라우저 자동 테스트 → 웹 페이지로 바로 띄워 휴대폰으로 확인하며 반복 수정
- **내가 개입한 지점**: 본회의 통과·변경점 중심으로 방향 전환 / "누진세율이면 항목별 합계가 틀린다"고 지적해 통합 계산 도입 / 등기·미등기, 다주택 중과 반영 요구 / 배포 404 오류를 AI와 함께 원인 추적
- **배운 점**: AI는 빠르게 만들지만, 정확도는 사람이 던지는 질문의 수준만큼 올라간다

## 2026.10.20 — 항목 확장과 요건 해설

- **한 일**: 근로장려금·업무용 승용차·육아휴직 공제 추가, 요건 해설 탭과 재산·필요경비 계산기
- **AI 활용 방식**: 요청 한 번으로 조사 → 구현 → 테스트 → GitHub 커밋 → 노션 기록까지 자동 처리
- **내가 개입한 지점**: 후보 선별 기준 제시 / 재산 vs 순자산, 공시가격 vs 실거래가 구분 요구 / 탭 UI 제안 / AI가 출처 없이 쓴 양도세 요건은 교재로 검증하기로 결정
- **배운 점**: AI에게 모르는 부분을 밝히게 하고, 사람이 검증 책임을 지는 구조가 필요하다
- **다음**: 양도세 요건 탭 교재 검증, 12월 본회의 결과 반영
- **추가 (피드백 반영)**: 항목을 세로 스크롤 대신 옆으로 넘기는 카드(스와이프·화살표·항목 칩)로 변경. "−/+ 부호가 헷갈린다"는 피드백을 받아 금액 옆에 "세금을 덜 내요 / 더 내요" 문구 표시
- **추가 (피드백 반영)**: "색이 어둡고 많아 직관적이지 않다"는 피드백 → 다크 모드 제거, 밝은 배경 고정, 색을 회색 계열 + 파랑(강조) + 초록(덜 내요) + 빨강(더 내요)으로 단순화
- **추가 (피드백 반영)**: "일반인은 취지에 관심이 적다"는 판단으로 카드 안을 [계산하기 / 요건 알아보기 / 개정 취지] 탭으로 분리. 기본은 계산하기만 보이게

## 2026.10.21 — 시행령 확인 표시

- **한 일**: 시행령에서 세부 기준이 정해지는 4개 항목에 '시행령 개정으로 확인 예정' 표시 추가, 확정되면 내용이 표시되는 구조. 중과 주택 수 설명 문구 수정
- **AI 활용 방식**: AI에게 '지방 3억원 이하 제외' 근거를 물어 출처 확인 → AI가 학습 지식으로 쓴 부분임을 스스로 밝히고 조문(소득령 167조의3·10)과 부정확한 표현(공시가격→기준시가, 지역 범위, 비과세와 혼동 가능성)을 찾아냄
- **내가 개입한 지점**: AI 답변의 근거를 캐물어 검증, 미확정 세부 기준은 시행령 개정 시점과 연결해 표시하자고 설계
- **배운 점**: AI의 답을 그대로 쓰지 않고 '어디서 나온 지식인지' 묻는 것만으로 오류가 드러난다
- **추가 (피드백 반영)**: 가격 기준이 확인되지 않은 '지방 저가주택 제외' 설명은 삭제하고 본회의 통과안·시행령이 나오면 쓰기로. 설명은 가독성을 위해 세세하게 늘리지 않기로 결정
- **추가 (버그 수정)**: 카드를 넘길 때 상단 칩·번호가 실제 카드와 어긋나는 오류(예: 6 / 5) 수정. 위치 계산을 '화면에 가장 가까운 카드' 기준으로 바꾸고 범위를 고정. 모든 세목에서 이전/다음·칩·스와이프를 휴대폰·PC로 검사하는 자동 테스트를 추가해, 수정 전 코드에서는 실패하고 수정 후 통과하는 것까지 확인. 앞으로 배포 전마다 실행
- **추가**: 고객 서비스 방향에 맞춰 하단에 '정확한 판단은 전문가 상담으로' 상담 연결 영역과 가상의 '백 회계법인 세무자문본부' 표기 추가 (가상 법인·데모임을 명시). 짧은 카드 아래 빈 공간이 생기던 문제도 카드 높이에 맞추도록 고치고 테스트에 검사 추가

## 2026.10.21 (저녁) — 세목을 엮은 '내 집 한 채' 시뮬레이터

- **한 일**: 취득세·재산세·종부세를 추가하고, 집 정보를 한 번 입력하면 살 때(취득세) → 갖고 있을 때(재산세·종부세) → 팔 때(양도세)의 세금을 이어서 계산하는 '내 집 한 채' 탭을 첫 화면으로. 일시적 2주택 처분기한을 양도세·취득세·종부세 세 세금의 타임라인으로 확장
- **AI 활용 방식**: 지방세제 개편안과 종부세 정부안을 AI가 조사·대조 → 세목별 계산을 하나의 입력으로 연결 → 수계산 검산과 자동 테스트
- **내가 개입한 지점**: "양도세와 취득세·재산세는 관련이 많으니 엮자"는 문제 제기 / 시행령으로 세부 기준이 정해지는 항목은 제외 / 재산세 대신 실질 변화가 있는 종부세를 넣기로 결정
- **배운 점**: 세목별(법 조문 관점)이 아니라 고객의 '집 한 채' 관점으로 묶으니 취득세가 양도세 필요경비로 이어지는 연결이 자연스럽게 드러난다
- **추가 (피드백 반영)**: "양이 너무 많게 느껴진다"는 피드백 → 세목별 세액 효과를 첫 화면 '한눈에 보기' 탭으로 분리하고 2열로 압축. 세부 내용은 각 세목 탭에서 보도록
