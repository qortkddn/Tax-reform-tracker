# 프로젝트 일지

세법 개정을 AI로 추적·계산하는 트래커. 세법 지식 자체보다 **세법을 AI와 어떻게 엮어 일하는가**(역할 분담·검증·도구 연동)를 기록합니다.

## AI 활용 구조

| 단계 | AI가 한 일 | 내가 한 일 |
| --- | --- | --- |
| 조사 | 웹 검색으로 정부안·보도자료 수집, 출처 표시 | 의미 있는 항목 선별, 실질 영향 없는 항목 제외 기준 제시 |
| 설계 | 화면 구조와 계산 흐름 제안 | 핵심 가치 정의, 방향 수정(국회 심의 현황 → 본회의 통과·변경점) |
| 계산 | 세법 수식을 코드로 구현 | 세법 논리 오류 지적(누진세율, 등기/미등기, 재산 평가 기준) |
| 검증 | 헤드리스 브라우저 자동 테스트, 수계산 대조 | 세법적 타당성 검토, 출처 없는 부분 교재로 재검증 |
| 배포·기록 | GitHub 커밋, Pages 배포, 노션 일지 업데이트 | GitHub 앱·노션 연동 설정 |

## AI 활용 원칙

1. 숫자는 AI가 말로 추정하지 않고 코드로 계산한다
2. 미확정·미확인 정보는 화면에 '가정'으로 표시하고 출처를 붙인다
3. AI 결과는 반드시 실행해서 검증하고, 세법 지식으로 한 번 더 본다
4. AI가 출처 없이 쓴 내용은 스스로 밝히게 하고, 검증 책임은 내가 진다
5. AI에게 선별 기준을 준다 — 실질 영향이 있는 것만

- **내가 개입한 지점**: 최저한세 개념보다 '이월된다'는 게 고객 돈에 직결되니 그걸 설명하자 → 이월공제(10년) 행과 설명 추가 / 자기주식 주주 과세는 종합소득세(배당소득 증가)만이 아니라 양도소득세(주택 외)에서 세금이 빠지는 것도 따로 보여야 한다 → 같은 입력으로 두 탭에 나눠 표시하고 합치면 거래 전체 변화가 되도록 / 법인세는 회사 세금이라 '내 세금'과 섞이면 안 된다 → 회사명 입력, 요약에 '○○(주) 법인세'로 표시
- **배운 점**: 같은 거래도 세목별로 쪼개 보여줘야 고객이 '어디서 늘고 어디서 줄었는지' 이해한다. 합계와 세목별 내역이 서로 맞는지 테스트로 확인
- **검증 — Gross-up**: AI가 Gross-up을 10%로 넣었는데, 내가 "법인세율이 다시 올랐으니 애매하다"고 지적 → 확인해 보니 2025년 개정세법(12.2 본회의)에서 법인세율 인상에 맞춰 10% → 11%로 바뀌었고 2027.1.1 지급분부터 적용. 의제배당은 2027년 이후 발생하므로 11%로 수정하고 테스트 추가. 법인세율 10·20·22·25%, 최저한세율, 대주주 양도세율은 내가 검증 완료
- **검증 — 조특법 §127④**: 내가 "창업감면과 통합투자세액공제는 하나만 선택"이라고 조문을 짚음 → 두 경우를 모두 계산해 세금이 적은 쪽을 고르도록 구현, 법인세 통합 계산에도 창업감면 포함. 최저한세는 100% 감면만 제외하고, 걸리면 공제(이월)부터 배제한 뒤 감면(소멸) 순서로 반영. 테스트 33 → 36건

## 2026.10.26 (오후) — 공공데이터로 조문 대조 (데이터마이닝)
- **한 일**: 법제처 국가법령정보 Open API로 조문을 수집하는 스크립트 + 매주 자동 수집(GitHub Actions) + 조문 원문에서 세율·금액 구간을 뽑아 계산 코드의 숫자와 대조하는 테스트. 계산에 쓰는 세율을 상수(GU, MTR 등)로 분리해 조문과 1:1로 대조 가능하게 함
- **AI 활용 방식**: 정형화되지 않은 법조문 텍스트에서 '6퍼센트', '100분의 11', '1억5천만원' 같은 표현을 규칙(정규식)으로 추출 → 계산값과 자동 비교. 가짜 조문으로 먼저 검사기를 시험해 '1억5천만원' 같은 복합 단위와 띄어쓰기 때문에 숫자가 붙는 오류 2건을 찾아 고침. 일부러 법인세율을 틀리게 넣은 조문으로 실패하는 것까지 확인
- **내가 개입한 지점**: '법조문은 공공데이터포털에서 가져와 반영하자'는 아이디어 제시 → 지금까지 사람이 하던 '조문 대조'를 자동화하는 방향으로 연결. 인증키 발급은 내가 진행
- **배운 점**: AI가 기억으로 쓴 세율은 할루시네이션 위험이 있지만, 공식 원문과 기계적으로 대조하면 검증 비용이 0에 가까워진다. 다음 단계는 개정 시 자동 알림
- **다음**: 인증키(LAW_OC) 발급 → GitHub Secret 등록 → 첫 수집·대조 실행

## 참고 사례 — 광교세무법인 길혜전 세무사 '핀즈' (연합뉴스 2026.5.4)

- 비슷한 점: 전문가가 직접 기획한 AI 서비스, "할루시네이션은 전문가가 잡는다", 계산은 규칙 기반 코드 + AI 보조, 납세자를 위한 서비스
- 다른 점: 핀즈는 "지금 법에서 어떻게 절세하나"(양도·증여·부담부증여 비교, 청년 감면 경정청구), 이 시뮬레이터는 "법이 바뀌면 얼마나 달라지나"(현행→정부안→확정안). 세목 간 통합 계산, 자동 테스트 + 조문 원문 대조로 검증을 시스템화
- 참고 아이디어: 청년 소득세 감면(조특법 §30) 확대 여부 확인, 상증세 추가 시 양도 vs 증여 비교

## 면접 포인트 — 세 가지 관점

> AI가 빠르게 만들고, 데이터가 기계적으로 대조하고, 회계사가 판단하고 책임진다.

**① AI 할루시네이션을 어떻게 해결했나**
- 출처를 캐묻는다: "어디서 나온 지식이야?" → AI가 학습 지식임을 밝히고 부정확한 표현 3가지 수정
- 모르는 것은 '시행령 확인 예정', '판단 필요'로 표시 → 빈칸은 내가 조문으로 채움 (조특법 §127④, 창업감면 최저한세)
- 두 번째 출처로 교차 확인: Gross-up 10% → 개정세법·세법 강의로 2027년부터 11% 확정
- 숫자는 코드로, 오류는 테스트로 고정: 수계산 검산 36건 + 화면 테스트, 버그마다 재발 방지 테스트

**② 데이터마이닝을 어떤 방식으로 했나**
- 수집: 법제처 국가법령정보 Open API(공공데이터)로 계산에 쓰는 조문을 매주 자동 수집
- 추출: 비정형 법조문에서 '6퍼센트', '100분의 11', '1억5천만원'을 정규식으로 뽑아 정형 데이터(세율·구간)로 변환
- 대조: 계산 코드의 세율과 자동 비교 → 조문 개정 시 테스트가 먼저 알림
- 검사기 검증: 가짜 조문으로 오류 2건 수정, 일부러 틀린 세율로 실패 확인

**③ 회계사의 전문지식을 AI와 어떻게 엮었나**
- 역할 분담: AI는 조사·구현·테스트·배포, 나는 문제 정의·세법 판단·최종 검증
- 세법 구조를 계산에: 누진세율 통합 계산(단순합 +326만 vs 실제 +158만), 세액공제 → 최저한세 → 이월공제
- AI가 못 본 연결: 자기주식 개정 → 주주 소득세, 코인 = 기타소득·분리과세, 1세대 1주택·주택 수
- 고객의 언어로: 개념보다 돈(이월공제), 회사 세금과 개인 세금 구분 → 상담 연결로 매출
